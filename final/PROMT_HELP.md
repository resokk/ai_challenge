# Задача: справка по боту — 50 статей, RAG-индекс и MCP-сервер

Сделай в каталоге `final/help/` справочную систему для Telegram-бота из
`final/bot/`: 50 статей о том, как пользоваться ботом, семантический индекс
по ним на локальной модели эмбеддингов (через `transformers`) и MCP-сервер
с одним инструментом `help`: по вопросу он находит подходящие фрагменты
статей локальной моделью, отдаёт их DeepSeek на суммаризацию и возвращает
готовый короткий ответ со ссылками на статьи.

## Исходные данные: бот `final/bot/` и его ТЗ `final/PROMPT.md`

Справка пишется про конкретного бота — тот, что лежит в `final/bot/` и
сделан по ТЗ `final/PROMPT.md`. Это единственные источники фактов.

1. Прочитай `final/PROMPT.md` целиком: из него — назначение бота, модель
   доступа, задачи, git, инструменты, контекст и суммаризация, поведение,
   критерии готовности. По его разделам строится структура справки.
2. Прочитай код бота: `bot/README.md`, `bot/bot.py` (особенно `COMMANDS`,
   `HELP`, `GIT_HELP`, `TASKS_HELP`, тексты ответов и ошибок),
   `bot/admin.py`, `bot/git_ops.py`, `bot/tools/*`, `bot/context.py`,
   `bot/config.py`, `bot/.env.example`, `bot/prompts/system.md`, `bot/tests/`.
3. Где ТЗ и код расходятся, справка описывает поведение кода (его и увидит
   пользователь). Каждое такое расхождение выпиши в отчёте в конце работы.
   Код бота не меняй, кроме мест из раздела 7.

Ничего не выдумывай: если поведение не следует ни из ТЗ, ни из кода,
проверь его по тестам бота, а не предполагай. Команды, параметры,
переменные `.env`, лимиты и тексты сообщений берутся дословно из кода.

## Стек

- Python 3.11+.
- `transformers` + `torch` (CPU) — модель эмбеддингов
  `intfloat/multilingual-e5-small` (статьи на русском, нужна мультиязычная
  модель). Через `AutoTokenizer`/`AutoModel`, mean pooling по
  `attention_mask`, L2-нормализация. Префиксы e5 обязательны:
  `"passage: "` для фрагментов статей, `"query: "` для запросов.
  Без `sentence-transformers`, без Ollama, без внешних API.
- `numpy` — векторы; поиск — косинусная близость перебором (матрица
  ~несколько сотен фрагментов, FAISS и векторные БД не нужны).
- DeepSeek через `openai==1.51.2` (`base_url=https://api.deepseek.com`) —
  те же версии `openai`/`httpx`, что в `bot/requirements.txt` (и тот же
  комментарий про `httpx==0.27.2`). Ключ и модель — из `final/help/.env`
  (`python-dotenv`): `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` (по умолчанию
  `deepseek-chat`).
- `mcp==2.3.0` — сервер, как в `day_21/codeindex/server.py`
  (`from mcp.server.mcpserver import MCPServer`, transport
  `streamable-http`, `json_response=True`, `stateless_http=True`).
- `pytest`. Версии пакетов зафиксированы в `requirements.txt`.
- Без ORM, веб-фреймворков, LangChain/LlamaIndex и лишних слоёв.

## Структура

`final/help/` — самостоятельная часть, бот её не импортирует, общается с ней
только по MCP. Все пути разрешаются относительно каталога `help/`, а не
текущей директории запуска.

```
final/help/
  articles/          # 50 статей: NN-slug.md
  articles.py        # загрузка и проверка статей, разбиение на фрагменты
  embedder.py        # модель e5 через transformers: embed_passages, embed_query
  index.py           # построение/загрузка индекса, поиск
  answer.py          # поиск + суммаризация через DeepSeek
  server.py          # MCP-сервер с инструментом help
  prompts/
    answer.md        # системный промпт суммаризации
  .env.example
  requirements.txt
  README.md
  tests/
  .gitignore         # index/, .venv, .env
  index/             # генерируется: vectors.npy, chunks.json (в git не идёт)
```

## 1. Статьи

### Формат

Файл `articles/NN-slug.md` (`NN` — 01…50, порядок чтения), в начале —
front matter:

```markdown
---
id: register
title: Как получить доступ к боту
category: start
commands: [/start]
related: [first-steps, admin-approve]
---

# Как получить доступ к боту

Коротко: что это и когда нужно (1–2 предложения).

## Как сделать
...

## Что может пойти не так
...
```

- `id` — уникальный slug, совпадает с частью имени файла после `NN-`.
- `category` — одна из: `start`, `tasks`, `git`, `files`, `run`, `chat`,
  `tools`, `admin`, `troubleshooting`, `examples`.
- `commands` — команды бота, которые статья описывает (может быть пустым).
- `related` — id существующих статей.
- Объём 150–500 слов, на русском, простым языком для пользователя Telegram,
  не для разработчика бота. Внутреннее устройство (root, `run_as`, SQLite) —
  только в статьях категории `admin` и там, где это объясняет поведение,
  видимое пользователю (например, почему нельзя выйти за рабочую копию).
- Каждая статья отвечает на один вопрос. Заголовки `##` осмысленные — по ним
  статья режется на фрагменты.
- Точные тексты команд, сообщений бота и ошибок — дословно из кода, в
  `` `code` ``. Примеры диалога — блоками «Вы: … / Бот: …».

## 2. Разбиение на фрагменты (`articles.py`)

- `load_articles(dir) -> list[Article]`: разбор front matter (простой
  разбор `key: value` и `[a, b]`, без PyYAML) и тела. Ошибка с именем файла,
  если поле отсутствует, `id` не уникален или не совпадает с именем файла,
  `category` неизвестна, `related` ссылается на несуществующий id.
- `chunk(article) -> list[Chunk]`: фрагмент = заголовок статьи + одна
  секция `##` (вступление до первой `##` — отдельный фрагмент). Каждый
  фрагмент начинается с `"{title}. {section}\n"`, чтобы его эмбеддинг знал,
  о чём статья. Секция длиннее ~1200 символов режется по абзацам.
- `Chunk`: `article_id`, `title`, `section`, `text`.

## 3. Эмбеддинги (`embedder.py`)

- Модель грузится лениво один раз; имя — константа
  `MODEL = "intfloat/multilingual-e5-small"`, переопределяется переменной
  окружения `HELP_EMBED_MODEL` (нужно тестам и офлайн-запуску).
- `embed_passages(texts) -> np.ndarray` и `embed_query(text) -> np.ndarray`:
  префиксы e5, батчи по 32, `max_length=512`, `torch.no_grad()`, mean
  pooling, L2-норма, `float32`.
- Модель скачивается с Hugging Face при первом запуске; дальше работает из
  кэша без сети. Ошибку загрузки модели превращай в понятное сообщение.

## 4. Индекс (`index.py`)

- `build(articles_dir, index_dir)`: фрагменты всех статей → `vectors.npy` и
  `chunks.json` (фрагменты + имя модели + sha256 от содержимого всех
  статей).
- `load_or_build(...)`: если индекса нет, модель другая или хэш статей не
  совпадает — перестроить; иначе загрузить. Сервер вызывает это при старте.
- `search(query, k, category=None) -> list[Hit]`: косинус = скалярное
  произведение нормированных векторов; фильтр по категории статьи; из одной
  статьи в выдаче не больше двух фрагментов. `Hit`: `article_id`, `title`,
  `section`, `score` (округлить до 3 знаков), `text`.
- CLI: `python index.py build` — перестроить принудительно,
  `python index.py search "вопрос" [-k 5]` — проверить выдачу глазами.

## 5. Ответ на вопрос (`answer.py`)

`async answer(question: str) -> str`:

1. Пустой или длиннее 1000 символов вопрос → ошибка с понятным текстом.
2. `search(question, k=5)` — локальная модель e5, не больше двух фрагментов
   из одной статьи.
3. Фрагменты отдаются DeepSeek: системный промпт из `prompts/answer.md`,
   в пользовательском сообщении — вопрос и фрагменты в виде
   `[article_id] title — section\ntext`. Асинхронный клиент `AsyncOpenAI`,
   `temperature=0.2`, таймаут 60 с.
4. Возвращается текст ответа модели и в конце строка
   `Статьи: title (id), …` — статьи, из которых были фрагменты.

Промпт `prompts/answer.md` (на русском):
- Ты отвечаешь на вопрос пользователя о Telegram-боте только по
  приведённым фрагментам справки.
- Отвечай на языке вопроса, коротко: сначала суть, затем шаги; команды,
  параметры и тексты сообщений бота — дословно из фрагментов, в `code`.
- Не добавляй команд, параметров и возможностей, которых нет во
  фрагментах. Если фрагменты не отвечают на вопрос — так и скажи одной
  фразой и назови ближайшие по теме статьи.

Ошибка DeepSeek (сеть, таймаут, ключ, лимит) не роняет инструмент: в лог
пишется причина, а возвращаются найденные фрагменты как есть с пометкой
`Суммаризация недоступна, найденные фрагменты справки:`.

CLI для проверки: `python answer.py "вопрос"` печатает ответ.

## 6. MCP-сервер (`server.py`)

Streamable HTTP на `127.0.0.1:8770` (только loopback), путь `/mcp`. Индекс,
модель e5 и `.env` загружаются при старте, до приёма запросов; без
`DEEPSEEK_API_KEY` сервер не стартует (сообщение в stderr, код 1).

Один инструмент:

- `help(question: str)` — ответ на вопрос о самом боте: как получить
  доступ, команды, задачи и репозитории, git и SSH-ключи, запуск кода и
  pip, история и контекст, инструменты, администрирование, ошибки бота,
  примеры. Возвращает готовый ответ со ссылками на статьи справки.
  Описание инструмента — на русском и такое, чтобы модель бота звала его на
  любые вопросы «как в этом боте сделать X».

Неверные аргументы → `ToolError` с понятным текстом.

## 7. Подключение к боту

Минимальные изменения в `final/bot/`:

- `bot/mcp.json` — добавить сервер `"help": {"url": "http://127.0.0.1:8770/mcp"}`.
  Инструмент появится как `help__help` — механизм уже есть в
  `tools/mcp_client.py`, код клиента не трогать.
- `bot/prompts/system.md` — короткий абзац: на вопросы о самом боте
  (команды, настройка, ошибки бота, «как сделать X в боте») вызывай
  `help__help` с вопросом пользователя и передавай ответ по существу, не
  пересказывая его заново и не добавляя команд, которых в нём нет.
- Пользователь может спросить справку и сам:
  `/tool help__help {"question": "как подключить приватный репозиторий"}`.
- `bot/README.md` — раздел про `mcp.json` дополнить сервером `help` со
  ссылкой на `final/help/README.md`.

Бот должен продолжать работать, если сервер справки не запущен (это уже так:
недоступный MCP-сервер пропускается).

## 8. Тесты (pytest, без сети)

Реальная модель в обычных тестах не используется: `embedder` подменяется
детерминированным фейком (например, мешок слов → хэш-вектор фиксированной
размерности с L2-нормой), чтобы проверялась логика, а не модель. DeepSeek
подменяется фейковым клиентом, который запоминает запрос и возвращает
заданный текст или бросает исключение.

- Статьи: ровно 50 файлов, имена `01…50`, все проходят `load_articles`,
  объём каждой в пределах 150–500 слов, `related` валидны.
- Покрытие: каждая команда из `CommandHandler("…")` в `bot/bot.py`
  (вытащить регуляркой из исходника) и каждая подкоманда `/git`
  (`commit`, `push`, `diff`, `reset`, `ssh`) встречается в `commands` хотя
  бы одной статьи — тест падает, если в боте появится команда без справки.
- Фрагменты: разбиение по `##`, заголовок в начале, длинные секции режутся.
- Индекс: сборка, повторная загрузка без пересборки, пересборка при
  изменении статьи или имени модели, фильтр по категории, не больше двух
  фрагментов из статьи.
- `answer`: в запрос к DeepSeek попали вопрос, системный промпт и найденные
  фрагменты с id статей; к ответу добавлена строка `Статьи: …`; при
  исключении клиента возвращаются фрагменты с пометкой; пустой и слишком
  длинный вопрос отклоняются без запроса к DeepSeek.
- Сервер: сервер объявляет ровно один инструмент `help` со схемой
  `{question: string}`; вызов функции инструмента напрямую; ошибки
  аргументов → `ToolError`.
- `@pytest.mark.model` (пропускается, если модели нет в кэше HF): на
  настоящей модели e5 для ~10 вопросов в формулировках пользователя
  («как подключить приватный репо», «бот не пушит», «как запустить тесты»,
  «как удалить историю», …) нужная статья входит в top-3.

Установка (venv, `pip install -r requirements.txt`, `.env` с ключом

## Критерии готовности

- 50 статей, все факты подтверждаются кодом бота; тесты покрытия команд
  проходят.
- `python index.py search "как добавить ssh ключ в github"` на настоящей
  модели первым выдаёт статью про `/git ssh`.
- `python answer.py "как закоммитить изменения"` возвращает короткий ответ
  с `/git commit` и строкой `Статьи: …`.
- Сервер стартует, бот при запуске видит в `/tools` один инструмент справки
  `help__help`, и на вопрос «как мне закоммитить изменения?» модель бота
  вызывает его и отвечает по полученному ответу.
- `pytest` в `final/help/` и в `final/bot/` зелёные.
