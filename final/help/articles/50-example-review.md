# Пример: ревью изменений перед push

Сценарий: модель сделала несколько правок. Прежде чем отправить их в GitHub,
проверяем, что изменилось, исправляем замечания ревью и только потом
коммитим и пушим.

## 1. Что изменено

Вы: /git
Бот:
```
Ветка: main → origin/main
Впереди: 0, позади: 0
Изменения:
  изменён: app/config.py
  изменён: app/main.py
  новый: debug.py
```

Сразу видно лишнее: `debug.py` вы не просили.

## 2. Ревью

Вы: /git diff
Бот: app/config.py — добавлено чтение таймаута из переменной окружения.
app/main.py — новый параметр timeout передаётся клиенту.
debug.py — новый файл с отладочным выводом настроек.
Риски: в app/main.py остался print(settings) — выводит настройки, включая
токен; debug.py, судя по всему, временный.

## 3. Исправление замечаний

Вы: Убери print(settings) из app/main.py.
Бот: Убрал print(settings) из app/main.py. Проверьте: /git diff.

С `debug.py` сложнее: удалять файлы модель не умеет, а `/git commit` берёт все
изменения сразу, выбрать отдельные файлы нельзя. Варианты:

- откатить всё `/git reset` и попросить модель повторить нужные правки без
  `debug.py`;
- попросить модель создать скрипт `cleanup.py`, который удаляет `debug.py` и
  сам себя, и запустить его: `/run cleanup.py`.

## 4. Повторное ревью и коммит

Вы: /git
Бот: … изменён: app/config.py, изменён: app/main.py

Вы: /git diff
Бот: … Рисков не видно.

Вы: /git commit Read client timeout from environment

## 5. Отправка

Вы: /git push
Бот: Изменения отправлены.

## Чек-лист перед push

- `/git` — нет лишних файлов, правильная ветка, `Впереди:` столько коммитов,
  сколько вы ожидаете.
- `/git diff` — нет забытых `print`, отладочного кода и секретов.
- `/run -m pytest` — тесты проходят.
- Сообщение коммита понятное: проверьте его в ответе `/git commit`.

Если что-то пошло совсем не так — `/git reset` вернёт рабочую копию к
последнему коммиту (после подтверждения кнопкой).
