# Лимиты на запуск: время, память, файлы, процессы

Сколько может работать ваш скрипт, сколько памяти ему доступно, сколько
процессов можно запустить. Всё, что бот запускает для вас, — ваш код, pip,
git — работает с ограничениями по времени и ресурсам. Это защищает сервер и
других пользователей от зависших и слишком жадных программ.

## Лимиты по умолчанию

Администратор может изменить эти значения в настройках бота.

- **Время `/run`** — 60 секунд. Потом программа останавливается вместе со
  всеми дочерними процессами.
- **Время pip** — 5 минут на установку пакетов.
- **Время git** — 60 секунд на одну команду git (клонирование, push).
- **Процессорное время** — 600 секунд на процесс.
- **Память** — 1024 МБ адресного пространства на процесс. При превышении
  программа обычно падает с `MemoryError`.
- **Размер файла** — до 512 МБ на один записываемый файл.
- **Число процессов** — до 128 одновременно для всех ваших процессов вместе.
  Это защищает от «fork-бомб».

## Что происходит при таймауте

В заголовке вместо кода выхода — `таймаут`, а в конце stderr —
`[таймаут: процесс убит через 60 с]`. Остановлена вся группа процессов,
включая запущенные программой дочерние.

## Одна операция за раз

Ваши команды выполняются строго по очереди: пока идёт `/run`, `/pip`,
клонирование или ответ модели, следующее сообщение ждёт своей очереди.
Команды других пользователей от этого не зависят.

## Чего лимиты не ограничивают

- Доступ в сеть не ограничен: программа может скачивать данные и обращаться к
  внешним сервисам.
- Общие ресурсы сервера (процессор, диск, каталог `/tmp`) делятся с другими
  пользователями; лимиты лишь сдерживают отдельный процесс.

## Что может пойти не так

- Тесты не успевают за 60 секунд — запускайте их частями:
  `/run -m pytest tests/test_api.py` или `-k имя`.
- Бесконечный цикл или ожидание ввода — программа будет остановлена по
  таймауту; ввода с клавиатуры у программы нет.
- `MemoryError` или внезапное падение на больших данных — уменьшите объём
  данных или обрабатывайте их частями.
- Ошибки вида «Resource temporarily unavailable» при запуске потоков или
  процессов — достигнут лимит числа процессов.
