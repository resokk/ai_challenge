# Создать задачу из репозитория GitHub

Команда `/tasks <id> <repo>` создаёт задачу, привязывает к ней репозиторий
GitHub, делает её активной и клонирует репозиторий в рабочую копию.

## Как сделать

Отправьте `/tasks`, id задачи и репозиторий в одном из форматов:

- `/tasks api octo/api`
- `/tasks api https://github.com/octo/api`
- `/tasks api https://github.com/octo/api.git`

Все три варианта сохранятся одинаково: `https://github.com/octo/api`. Пока идёт
клонирование, бот показывает `Клонирую https://github.com/octo/api…`, потом
отвечает:

Бот: Активная задача: api — https://github.com/octo/api
Рабочая копия готова.

## Как клонируется репозиторий

Если у вас уже есть SSH-ключ (`/git ssh`), бот клонирует по SSH
(`git@github.com:owner/name.git`) — так работают и приватные репозитории. Если
ключа нет — по HTTPS, а так получится только с публичными репозиториями. Push
в любом случае идёт по SSH.

Существование репозитория при создании задачи не проверяется — ошибку покажет
клонирование.

## Смена репозитория у задачи

Если задача с таким id уже есть, команда заменит её репозиторий, переключится
на неё и склонирует новый. Память задачи при этом сохраняется.

## Что может пойти не так

- `Репозиторий: owner/name или https://github.com/owner/name` — формат не
  подошёл. Не принимаются `http://`, другие сайты (GitLab и т. п.), адрес вида
  `git@github.com:owner/name.git` и пути с лишними частями (`owner/name/tree`).
- `id задачи: 1–64 символа из A-Z, a-z, 0-9, _, ., -` — неверный id.
- `Клонировать не удалось:` и текст ошибки git, затем подсказка
  `Если репозиторий приватный — создайте ключ /git ssh, добавьте его в GitHub
  и повторите /tasks <id>`. Задача при этом всё равно создана и активна —
  после исправления просто повторите `/tasks <id>`.
- Если в прежней рабочей копии были незакоммиченные изменения, бот
  предупредит: `⚠️ В прежней рабочей копии были незакоммиченные изменения —
  они потеряны.`
