# Работа с приватными репозиториями

Приватный репозиторий бот может склонировать только по SSH — вашим ключом из
`/git ssh`. Без ключа доступны лишь публичные репозитории.

## Как подключить приватный репозиторий

1. Создайте ключ: `/git ssh`. Бот покажет публичный ключ.
2. Добавьте ключ в GitHub:
   - в профиль — Settings → SSH and GPG keys → New SSH key (доступ ко всем
     вашим репозиториям), или
   - в репозиторий — Settings → Deploy keys (только этот репозиторий;
     отметьте `Allow write access`, если будете делать `/git push`).
3. Создайте задачу: `/tasks api octo/private-api`. Если задача уже создана,
   просто повторите `/tasks api`.
4. Бот ответит `Рабочая копия готова.` — можно работать.

## Пример

Вы: /tasks api octo/private-api
Бот: Активная задача: api — https://github.com/octo/private-api
Клонировать не удалось:
(текст ошибки git)
Если репозиторий приватный — создайте ключ /git ssh, добавьте его в GitHub и повторите /tasks api

Вы: /git ssh
Бот: Создан новый SSH-ключ.
Публичный ключ: …

…вы добавляете ключ в GitHub…

Вы: /tasks api
Бот: Активная задача: api — https://github.com/octo/private-api
Рабочая копия готова.

## Как это устроено

Если ключ есть, бот клонирует по адресу `git@github.com:owner/name.git`. Если
ключа нет — по HTTPS `https://github.com/owner/name.git`, без логина и пароля:
бот не спрашивает пароль и не принимает токены, поэтому приватный репозиторий
так не склонировать. Push всегда идёт по SSH.

При первом подключении к GitHub бот автоматически запоминает его ключ хоста —
ничего подтверждать не нужно.

## Что может пойти не так

- Ключ добавлен, но клонирование всё равно не удаётся — проверьте, что ключ
  добавлен в нужный репозиторий или в аккаунт, у которого есть к нему доступ,
  и что вы повторили `/tasks <id>` после добавления.
- Клонирование работает, а push — нет: у Deploy key не отмечено
  `Allow write access`.
- `Репозиторий: owner/name или https://github.com/owner/name` — адрес вида
  `git@github.com:owner/name.git` бот не принимает; укажите `owner/name`.
