# Запуск модуля: /run -m pytest, ruff и другие

`/run -m <module>` запускает модуль Python так же, как `python -m` в
терминале. Так запускают тесты, линтеры и команды установленных пакетов.

## Как сделать

1. Поставьте нужный инструмент в venv: `/pip pytest` (или `/pip ruff`,
   `/pip mypy`).
2. Запустите:
   - `/run -m pytest` — все тесты проекта;
   - `/run -m pytest -q tests/test_api.py` — один файл тестов;
   - `/run -m pytest -k parser -x` — тесты по имени, до первой ошибки;
   - `/run -m ruff check .` — проверка стиля;
   - `/run -m mypy app` — проверка типов.

Модуль запускается из корня рабочей копии активной задачи, Python — из вашего
venv. Аргументы после имени модуля передаются ему как есть.

Можно запускать и модули стандартной библиотеки, например
`/run -m json.tool data.json`.

## Пример

Вы: /run -m pytest -q
Бот: python -m pytest -q
код выхода 1, 2.4 с
Бот: stdout (кратко, полный вывод — в файле):
Прошло 14 тестов, упал 1: tests/test_parser.py::test_empty — AssertionError…
Бот: (файл stdout.txt)

Длинный вывод бот пересказывает с помощью модели, а полный присылает файлом.

## Модель тоже умеет запускать

Попросите: «запусти тесты и почини, что упадёт». Модель вызовет тот же
инструмент `run_python` с `module=true`, прочитает вывод и код выхода и
продолжит работу.

## Что может пойти не так

- В stderr `No module named pytest` — модуль не установлен: `/pip pytest`.
- `Ошибка: «os; rm» — не имя модуля` — имя модуля может содержать только
  буквы, цифры, `_` и точки и не начинаться с цифры.
- `Использование: /run <file.py> [args…] или /run -m <module> [args…]` —
  после `-m` не указан модуль.
- `Ошибка: нет активной задачи с рабочей копией — выберите её: /tasks <id>`.
- `таймаут` — тесты шли дольше 60 секунд. Запускайте их частями
  (`-k`, отдельный файл).
