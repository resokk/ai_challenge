# Перегенерация ключа: /git ssh new и её последствия

`/git ssh new` удаляет ваш SSH-ключ и создаёт новый. После этого старый ключ в
GitHub перестаёт работать, и новый нужно добавить заново.

## Когда это нужно

- вы подозреваете, что ключ скомпрометирован;
- вы хотите начать с чистого листа и заменить ключ во всех местах GitHub.

Если вы просто удалили ключ в GitHub по ошибке или не можете его найти,
перегенерировать не нужно: `/git ssh` покажет тот же ключ, и его можно
добавить снова.

## Как сделать

1. Отправьте `/git ssh new`. Подтверждения не будет — ключ заменяется сразу.
2. Бот ответит `⚠️ Создан новый ключ: старый ключ в GitHub больше не работает —
   замените его.`, затем `Публичный ключ:` и новый ключ.
3. В GitHub удалите старый ключ (Settings → SSH and GPG keys или Deploy keys
   репозитория) и добавьте новый. Для Deploy key снова отметьте
   `Allow write access`.
4. Проверьте: `/git push` или `/tasks <id>` для приватного репозитория.

## Последствия

- Пока новый ключ не добавлен в GitHub, `/git push` и клонирование приватных
  репозиториев не работают.
- Если ключ был добавлен как Deploy key в нескольких репозиториях, заменить
  его нужно в каждом.
- Рабочая копия и коммиты не затрагиваются: меняется только ключ.

## Что может пойти не так

- `push не удался:` с подсказкой `Нет доступа: добавьте ключ из /git ssh в
  GitHub (SSH keys или Deploy key с правом записи).` — новый ключ ещё не
  добавлен.
- `/git ssh` с любым другим словом вместо `new` (например, `/git ssh reset`)
  не меняет ключ: бот покажет справку по `/git`.
