# Какие инструменты есть: /tools

`/tools` показывает каталог инструментов — тот же самый, что видит модель:
название, описание и параметры каждого инструмента.

## Как сделать

Отправьте `/tools`. Каталог начинается со строки
`Каталог инструментов. Вызывай их только через функцию call_tool …`, дальше
для каждого инструмента:

```
### read_file
Содержимое текстового файла с номерами строк; можно запросить диапазон строк.
Параметры (JSON Schema): {"type": "object", "properties": {"path": …}, …}
```

Каталог длинный, поэтому приходит несколькими сообщениями.

## Встроенные инструменты

Справочные:

- `pypi_package_info` — сведения о пакете с PyPI;
- `python_docs_link` — ссылка на документацию стандартной библиотеки;
- `current_datetime` — текущие дата и время UTC.

Файлы рабочей копии:

- `list_files`, `read_file`, `search_files`, `python_outline` — смотреть
  проект;
- `write_file`, `edit_file` — менять файлы.

Окружение и запуск:

- `pip_install`, `pip_list` — пакеты в вашем venv;
- `run_python` — запуск скрипта или модуля.

## Инструменты MCP-серверов

Если администратор подключил MCP-серверы, их инструменты тоже есть в каталоге
— с префиксом сервера: `<server>__<tool>`, например `help__help` у этой
справки.

## Как читать параметры

Параметры описаны в JSON Schema: `properties` — названия аргументов и их типы,
`required` — обязательные, `default` — значение по умолчанию. По ним удобно
составлять вызов `/tool`.

## Что может пойти не так

- В каталоге нет ожидаемого MCP-инструмента — сервер не поднялся при запуске
  бота и был пропущен. Сообщите администратору: инструменты сервера появятся
  после перезапуска бота.
- `/tools` отвечает `Доступа нет: …` — заявка ещё не одобрена.
