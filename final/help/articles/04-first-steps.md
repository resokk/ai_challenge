# Первые шаги после одобрения

Заявку одобрили — что дальше? Короткий порядок действий, чтобы начать работать
со своим проектом.

## Как сделать

1. Отправьте `/help` — бот покажет все команды.
2. Если репозиторий приватный или вы собираетесь отправлять изменения в
   GitHub, создайте SSH-ключ: `/git ssh`. Бот покажет публичный ключ — добавьте
   его в GitHub (Settings → SSH and GPG keys или Deploy keys репозитория с
   отметкой Allow write access).
3. Создайте задачу и привяжите к ней репозиторий:
   `/tasks myproj owner/name`. Бот склонирует репозиторий в вашу рабочую копию.
4. По желанию задайте память задачи (`/memory используем FastAPI и pytest`) и
   пришлите файлом AGENTS.md с правилами проекта.
5. Пишите обычными сообщениями: «что делает этот проект?», «найди, где
   читается конфиг». Модель сама посмотрит файлы.
6. Чтобы запускать тесты, поставьте pytest в свой venv: `/pip pytest`, затем
   `/run -m pytest`.

## Пример

Вы: /tasks myproj octo/demo
Бот: Активная задача: myproj — https://github.com/octo/demo
Рабочая копия готова.

Вы: Какие модули есть в проекте и что они делают?
Бот: (модель смотрит файлы и отвечает по ним)

## Можно ли без задачи

Да. Без задачи можно задавать любые вопросы по Python, искать пакеты на PyPI,
ставить пакеты `/pip`. А вот работа с файлами, `/run`, `/memory` и `/git`
(кроме `/git ssh`) требуют активной задачи — без неё бот подскажет
`Нет активной задачи — выберите её: /tasks <id>`.

## Что может пойти не так

- `Клонировать не удалось:` — чаще всего репозиторий приватный, а ключа нет
  или он не добавлен в GitHub. Сделайте `/git ssh`, добавьте ключ и повторите
  `/tasks myproj`.
- `/run -m pytest` пишет в stderr, что модуля `pytest` нет, — сначала
  `/pip pytest`.
