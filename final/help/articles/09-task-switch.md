# Список задач и переключение между ними

`/tasks` показывает ваши задачи, а `/tasks <id>` делает одну из них активной.
При переключении рабочая копия создаётся заново.

## Список задач

Вы: /tasks
Бот:
```
Задачи:
• api — https://github.com/octo/api [память]
▶ web — https://github.com/octo/web
```

`▶` — активная задача, `•` — остальные, `[память]` — у задачи есть память.
Задачи идут по алфавиту id. Если задач нет, бот ответит
`Задач нет. Создайте: /tasks <id> <owner/name>`.

## Как переключиться

Отправьте `/tasks api`. Бот:

1. делает задачу `api` активной;
2. удаляет текущую рабочую копию целиком;
3. клонирует репозиторий задачи заново;
4. отвечает `Активная задача: api — https://github.com/octo/api` и
   `Рабочая копия готова.`

История диалога при этом не меняется. Модель продолжает тот же разговор, но
видит уже новую задачу и её память, а память прежней задачи — нет.

## Перед переключением

Рабочая копия у вас одна. Всё, что не отправлено в GitHub, при переключении
пропадёт:

- о незакоммиченных изменениях бот предупредит уже после переключения:
  `⚠️ В прежней рабочей копии были незакоммиченные изменения — они потеряны.`;
- о коммитах, которые вы не отправили `/git push`, бот не предупреждает —
  они тоже пропадут.

Поэтому перед переключением сделайте `/git commit` и `/git push`.

## Что может пойти не так

- `Задачи zzz нет. Есть: api, web` и подсказка по `/tasks` — такой задачи нет;
  создайте её `/tasks zzz owner/name`.
- Три и больше аргумента — бот покажет подсказку:
  `/tasks — список задач`, `/tasks <id> — переключиться`,
  `/tasks <id> <owner/name | https://github.com/owner/name> — создать или обновить`.
- `Клонировать не удалось:` — задача всё равно стала активной, но рабочей
  копии нет. Исправьте причину (часто — SSH-ключ) и повторите `/tasks <id>`.
