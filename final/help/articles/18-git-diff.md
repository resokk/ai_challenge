# Просмотр и ревью изменений: /git diff

`/git diff` отдаёт все незакоммиченные изменения модели на ревью и присылает
краткий разбор: что изменено, зачем и какие есть риски.

## Как сделать

Отправьте `/git diff`. Бот соберёт:

- изменения отслеживаемых файлов относительно последнего коммита;
- список новых файлов, которые git ещё не отслеживает (только имена, без
  содержимого).

Всё это отправляется модели отдельным запросом, и бот присылает ответ на
русском:

- что изменено по файлам;
- смысл изменений;
- замеченные риски — ошибки, забытые отладочные `print`, секреты в коде.

## Пример

Вы: /git diff
Бот: app/main.py — добавлен обработчик /health, возвращает статус и версию.
Риски: в строке с print(settings) выводятся настройки, включая токен, —
стоит убрать перед коммитом.

## Что важно знать

- Сам diff бот не выводит — только разбор модели. Список файлов покажет `/git`.
- Разбор не попадает в историю диалога: если хотите обсудить его с моделью,
  перешлите или перескажите нужную часть обычным сообщением.
- Большой diff обрезается до 20 000 символов (значение по умолчанию) с
  пометкой `[diff обрезан]` — модель видит только начало.
- Файлы из `.gitignore` в разбор не попадают.

## Что может пойти не так

- `Изменений нет.` — незакоммиченных изменений нет; модель при этом не
  вызывается.
- `Модель недоступна, попробуйте позже.` — запрос к модели не удался.
  Изменения не затронуты; повторите позже.
- `Нет активной задачи — выберите её: /tasks <id>` или
  `Нет рабочей копии — выберите задачу: /tasks <id>` — нет задачи или рабочей
  копии.
- `/git diff` с лишними словами (например, `/git diff main.py`) — бот покажет
  справку по `/git`: разбор всегда идёт по всем изменениям.
