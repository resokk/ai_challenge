# Запуск скрипта: /run file.py args

`/run` запускает Python-скрипт из рабочей копии активной задачи в вашем venv и
присылает его вывод.

## Как сделать

Отправьте `/run`, путь к скрипту и аргументы:

- `/run main.py`
- `/run scripts/report.py --month 2024-05`
- `/run main.py "аргумент с пробелами" second`

Аргументы разбираются как в командной строке: кавычки объединяют слова с
пробелами. Командная оболочка при этом не используется, поэтому `|`, `>`,
`&&` и переменные `$HOME` передаются скрипту как обычный текст.

Путь — относительно корня рабочей копии; скрипт запускается из корня рабочей
копии, поэтому относительные пути внутри скрипта считаются от него.
Интерпретатор — Python из вашего venv; при первом запуске бот создаёт venv
сам, это может занять немного времени.

## Пример

Вы: /run main.py --name Ann
Бот: python main.py --name Ann
код выхода 0, 0.3 с
Бот: stdout:
Hello, Ann!

Пока скрипт работает, бот показывает `выполняется run_python…`.

## Что важно знать

- Ввода нет: скрипт не может ничего прочитать из стандартного ввода
  (`input()` сразу получит конец ввода).
- Скрипт работает от имени вашей учётной записи: видит свои файлы, но не
  может прочитать файлы бота и других пользователей.
- Результат приходит только вам и не попадает в историю диалога. Если
  хотите обсудить его с моделью, попросите модель запустить скрипт самой —
  тогда она увидит вывод.

## Что может пойти не так

- `Использование: /run <file.py> [args…] или /run -m <module> [args…]` — не
  указан скрипт.
- `Не удалось разобрать аргументы (незакрытая кавычка?).` — проверьте кавычки.
- `Ошибка: файл не найден: main.py` — нет такого файла; проверьте путь.
- `Ошибка: путь вне рабочей копии` — запускать можно только файлы рабочей
  копии.
- `Ошибка: нет активной задачи с рабочей копией — выберите её: /tasks <id>`.
- В stderr `ModuleNotFoundError` — поставьте пакет: `/pip имя`.
- Заголовок `таймаут` — скрипт работал дольше 60 секунд и был остановлен.
