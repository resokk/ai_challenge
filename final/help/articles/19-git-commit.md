# Коммит изменений: /git commit

`/git commit` добавляет все изменения рабочей копии в коммит. Сообщение
коммита можно написать самому или поручить модели.

## Как сделать

- С сообщением: `/git commit Add health endpoint`. Всё после `commit`, вместе
  с переносами строк, станет сообщением коммита.
- Без сообщения: `/git commit`. Модель прочитает изменения и напишет
  сообщение сама: первая строка до 72 символов в повелительном наклонении, на
  английском (если по изменениям не видно, что в проекте принят другой язык),
  при необходимости — пустая строка и короткое описание.

Бот добавляет в коммит все изменённые, новые и удалённые файлы, кроме
указанных в `.gitignore`.

## Что ответит бот

```
Коммит 3f2a9c1

Add health endpoint

Файлы:
M	app/main.py
A	tests/test_health.py
```

Короткий хэш, сообщение и список файлов (`M` — изменён, `A` — добавлен,
`D` — удалён).

Автор коммита — ваше имя в Telegram (или имя пользователя), почта —
`<ваш telegram id>@users.noreply.telegram`.

## Коммит — ещё не отправка

Коммит сохраняется только в рабочей копии на сервере бота. Чтобы он появился
в GitHub, выполните `/git push`. Неотправленные коммиты пропадут при
переключении задачи или повторном клоне.

## Что может пойти не так

- `Нечего коммитить: рабочая копия чистая.` — изменений нет.
- `Нет активной задачи — выберите её: /tasks <id>` или
  `Нет рабочей копии — выберите задачу: /tasks <id>`.
- `Внутренняя ошибка, подробности в логе бота.` при `/git commit` без
  сообщения — модель не смогла написать сообщение (например, недоступна).
  Укажите сообщение сами: `/git commit Fix parser`.
- Сообщение модели не подошло — откатить коммит в боте нельзя. Следующий
  коммит с правильным сообщением можно сделать после новых правок.
