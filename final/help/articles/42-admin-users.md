# Одобрение, блокировка и удаление пользователей: admin.py

Статья для администратора. Пользователями управляет консольная утилита
`admin.py` в каталоге бота. Она работает с той же базой `bot.db`, что и бот.

## Команды

```bash
sudo .venv/bin/python admin.py list [--status pending|approved|blocked]
sudo .venv/bin/python admin.py approve <telegram_id>
sudo .venv/bin/python admin.py block <telegram_id>
sudo .venv/bin/python admin.py delete <telegram_id>
```

Все команды, кроме `list`, требуют root.

## list — список пользователей

Колонки: `id` (внутренний номер учётной записи), `telegram_id`, `status`,
`os user` (имя пользователя ОС, `user-<id>`) и имя с `@username`. Пустая база —
`Пользователей нет.` Новые заявки: `list --status pending`.

## approve — одобрить

Создаёт пользователя ОС `user-<id>` (по внутреннему `id`, не по
`telegram_id`) с домашним каталогом или разблокирует существующего, готовит
его каталоги и только потом меняет статус на `approved`. Печатает
`Одобрен: <telegram_id> (пользователь ОС user-<id>)` и отправляет
пользователю `Ваша заявка одобрена — можно работать. /help — список команд.`
Повторный `approve` после блокировки возвращает доступ со всеми данными.

## block — заблокировать

Блокирует пользователя ОС, завершает все его процессы и меняет статус на
`blocked`. Печатает `Заблокирован: <telegram_id>`, пользователь получает
`Ваш доступ к боту заблокирован администратором.` Рабочая копия, venv, ключ,
задачи и история сохраняются.

## delete — удалить

Завершает процессы, удаляет пользователя ОС вместе с домашним каталогом
(рабочая копия, venv, SSH-ключ), затем задачи, историю и запись пользователя.
Печатает `Удалён: <telegram_id> вместе с пользователем ОС, задачами и
историей`. Уведомление не отправляется; отменить удаление нельзя.

## Что может пойти не так

- `Ошибка: пользователя с telegram_id N нет` (код выхода 2) — пользователь ещё
  не отправлял `/start` или id указан неверно; сверьтесь с `list`.
- `Ошибка: пользователь ОС user-5 уже существует и не принадлежит боту`
  (код 1) — в системе есть чужой пользователь с таким именем; бот его не
  трогает и статус не меняет.
- Другая `Ошибка: …` с кодом 1 — системная команда не удалась; статус не
  изменён.
- `Предупреждение: уведомление не отправлено: …` — статус изменён, но
  сообщение пользователю не ушло. Пользователь узнает статус, отправив
  `/start`.
