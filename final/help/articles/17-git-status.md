# Статус рабочей копии: /git

`/git` без аргументов показывает, на какой вы ветке, сколько коммитов не
отправлено и какие файлы изменены в рабочей копии активной задачи.

## Как сделать

Отправьте `/git`. Пример ответа:

```
Ветка: main → origin/main
Впереди: 1, позади: 0
Изменения:
  изменён: app/main.py
  новый: tests/test_api.py
```

- `Ветка: main → origin/main` — текущая ветка и ветка GitHub, с которой она
  связана. Если связи нет: `Ветка: feature (без upstream)`.
- `Впереди: N` — локальные коммиты, ещё не отправленные `/git push`.
- `позади: N` — коммиты в GitHub, которых нет у вас (по состоянию на момент
  клонирования).
- `Изменения:` — файлы с незакоммиченными правками. Метки: `изменён`,
  `добавлен`, `удалён`, `переименован`, `скопирован`, `конфликт`,
  `изменён тип`, `новый` (файл ещё не отслеживается git).

Если правок нет, вместо списка — `Рабочая копия чистая.`

## Когда смотреть /git

- после того как модель правила файлы — какие файлы затронуты;
- перед `/git commit` — что попадёт в коммит;
- перед переключением задачи — не потеряете ли вы изменения или
  неотправленные коммиты.

Файлы из `.gitignore` в списке не показываются и в коммит не попадают.

## Подкоманды

`/git commit [сообщение]`, `/git push`, `/git diff`, `/git reset`,
`/git ssh [new]`. С любым другим аргументом `/git` покажет справку по ним.

## Что может пойти не так

- `Нет активной задачи — выберите её: /tasks <id>` — задача не выбрана.
- `Нет рабочей копии — выберите задачу: /tasks <id>` — задача есть, но
  рабочей копии нет (например, клонирование не удалось). Повторите
  `/tasks <id>`.
- `позади: 0`, хотя в GitHub есть новые коммиты: бот не обновляет сведения о
  GitHub сам. Свежее состояние даст только повторный клон `/tasks <id>`.
