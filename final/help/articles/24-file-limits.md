# Ограничения файловых инструментов

Файловые инструменты работают только внутри рабочей копии активной задачи и
не трогают каталог `.git`. Здесь — все ограничения и что означают ошибки.

## Только рабочая копия

- Пути указываются относительно корня рабочей копии: `app/main.py`,
  `tests/`.
- Абсолютные пути (`/etc/hosts`), выход наверх через `..` и символические
  ссылки, ведущие наружу, отклоняются с ошибкой `путь вне рабочей копии`.
  Где именно лежит рабочая копия на сервере, бот не раскрывает.
- Каталог `.git` закрыт и для чтения, и для записи:
  `путь вне рабочей копии: каталог .git закрыт`. Работайте с git через `/git`.

Почему так: инструменты выполняются от имени вашей учётной записи на
сервере, и права системы не пускают их к файлам бота и других
пользователей. Проверка путей — второй слой защиты с понятными ошибками.

## Какие файлы можно читать

- Только текстовые в UTF-8. Бинарные отклоняются:
  `бинарный файл, читать можно только текстовые`; другая кодировка —
  `файл не в UTF-8 (похоже на бинарный)`.
- Файлы больше 10 МБ не читаются: `файл слишком большой`.
- Поиск `search_files` пропускает бинарные файлы и файлы больше 2 МБ.
- Файлы из `.gitignore` не видны в `list_files` и `search_files`.

## Лимиты

Значения по умолчанию (администратор может их изменить):

- `read_file` отдаёт за раз до 20 000 символов, дальше — подсказка, с какой
  строки читать;
- `write_file` записывает до 1 000 000 байт;
- любой результат инструмента обрезается до 20 000 символов с пометкой
  `[обрезано: показано 20000 из N символов]`;
- инструмент должен ответить за 30 секунд, иначе
  `Ошибка: read_file не ответил за 30 с`.

## Чего нет

Удаления, переименования и перемещения файлов в инструментах нет. Если файл
действительно нужно удалить или переименовать, это можно сделать своим
скриптом через `/run` внутри рабочей копии; изменение покажет `/git`.

## Что может пойти не так

- `нет активной задачи с рабочей копией — выберите её: /tasks <id>` — нет
  активной задачи.
- `рабочей копии нет — выберите задачу: /tasks <id>` — задача выбрана, но
  рабочей копии нет (клонирование не удалось).
- `файл не найден` или `каталог не найден: …` — проверьте путь через
  `list_files`.
