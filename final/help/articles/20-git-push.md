# Отправка изменений в GitHub: /git push

`/git push` отправляет ваши коммиты в GitHub — в ветку с тем же именем, что и
текущая ветка рабочей копии.

## Как сделать

1. Закоммитьте изменения: `/git commit …`.
2. Отправьте `/git push`.
3. Бот ответит `Изменения отправлены.` и покажет вывод git.

Push всегда идёт по SSH вашим ключом из `/git ssh`, даже если репозиторий был
склонирован по HTTPS. Ключ должен быть добавлен в GitHub с правом записи.

## Пример

Вы: /git push
Бот: Изменения отправлены.
To github.com:octo/api.git
   1a2b3c4..3f2a9c1  HEAD -> main

## Чего бот не делает

Принудительный push (`--force`) не поддерживается: бот никогда не
перезаписывает чужие коммиты в GitHub. Объединять ветки (pull, merge,
rebase) бот тоже не умеет.

## Что может пойти не так

Если push не удался, бот пишет `push не удался:`, текст ошибки git и
подсказку:

- `В удалённой ветке есть коммиты, которых нет у вас; принудительный push не
  поддерживается.` — кто-то отправил коммиты в GitHub после вашего клона.
  Сохраните свои изменения, склонируйте репозиторий заново `/tasks <id>`
  (локальные коммиты при этом пропадут) и повторите правки.
- `Нет доступа: добавьте ключ из /git ssh в GitHub (SSH keys или Deploy key с
  правом записи).` — ключ не добавлен в GitHub, добавлен не в тот репозиторий
  или у Deploy key не отмечено `Allow write access`.
- `Проверьте доступ к репозиторию и повторите.` — другая ошибка; смотрите
  текст git над подсказкой.

Другие ответы:

- `SSH-ключа нет — создайте его: /git ssh, и добавьте в GitHub.` — ключа нет.
- `Нет активной задачи — выберите её: /tasks <id>` или
  `Нет рабочей копии — выберите задачу: /tasks <id>`.
- `/git push origin main` и другие аргументы не поддерживаются — бот покажет
  справку по `/git`.
