# День 23: реранкинг, фильтр релевантности и переписывание запроса

К семантическому поиску по коду из дня 22 (эмбеддинги Ollama в FAISS) добавлены этапы до и после векторного поиска:

```
запрос ──► [rewrite: LLM] ──► векторный поиск, fetch_k на запрос ──► [фильтр: min_score] ──► [rerank] ──► top k
           исходный + переписанный                                    косинусная близость    heuristic | llm
```

| Этап | Опция | Что делает |
|---|---|---|
| Переписывание запроса | `--rewrite` | LLM переводит вопрос на английский и добавляет вероятные имена функций и классов. Кандидаты по исходному и переписанному запросам объединяются, у каждого чанка остаётся лучший из двух скоров. |
| Топ-K до фильтрации | `--fetch-k N` | Сколько кандидатов на запрос попадает во второй этап (по умолчанию `k`). |
| Порог | `--min-score X` | Отбрасывает кандидатов с косинусной близостью ниже `X`. |
| Эвристический реранкер | `--rerank heuristic` | Близость плюс бонус за слова запроса (идентификаторы делятся по snake_case и CamelCase) в имени и коде чанка. |
| LLM-реранкер | `--rerank llm` | Отдельная модель оценивает каждого кандидата от 0 до 10. Кандидаты с оценкой ниже `--min-relevance` (по умолчанию 5) отбрасываются. |
| Топ-K после фильтрации | `-k N` | Сколько результатов вернуть. Если вернулось меньше или ничего, остальные недостаточно релевантны. |

LLM задаётся опцией `--llm` (по умолчанию `qwen2.5-coder:3b`) и работает через Ollama с temperature 0.

## Установка

```sh
uv venv -p 3.12 .venv && uv pip install -p .venv -r requirements.txt
ollama pull nomic-embed-text && ollama pull qwen2.5-coder:3b
git clone --depth 1 https://github.com/ormar-orm/ormar /tmp/ormar
.venv/bin/python -m codeindex index /tmp/ormar/ormar --chunking ast
```

## Поиск

```sh
python -m codeindex search "как удалить запись из базы" -k 5                     # обычный векторный поиск
python -m codeindex search "как удалить запись из базы" -k 5 --rewrite --min-score 0.62 \
       --fetch-k 20 --rerank llm                          # все этапы
python -m codeindex search "прогноз погоды на завтра" --min-score 0.62            # ничего релевантного: пустой ответ
```

MCP-сервер принимает те же опции при запуске: `python -m codeindex.server --rewrite --min-score 0.62 --rerank heuristic`.

## Сравнение режимов

В `eval/ormar.json` 19 вопросов по ORM ormar, у каждого перечислены qualified names правильных ответов:
11 вопросов на английском, 4 на русском и 4, на которые в коде ответа нет (пустой `relevant`).
Для последних правильный результат — пустой ответ.

```sh
python -m codeindex eval eval/ormar.json -v      # все 8 режимов
python -m codeindex eval eval/ormar.json --modes baseline filter --min-score 0.65
```

Метрики:
- **hit@k** — доля вопросов с ответом, у которых правильный результат попал в топ-k;
- **MRR** — среднее 1/ранг первого правильного результата;
- **precision** — доля правильных среди возвращённых результатов;
- **rejected** — доля вопросов без ответа, на которые вернулся пустой список;
- **avg results** — сколько результатов в среднем возвращается;
- **sec/query** — время на запрос.

### Результаты (k=5, min score 0.62, fetch k 20, min relevance 5)

| режим | hit@k | MRR | precision | rejected | avg results | sec/query |
|---|---|---|---|---|---|---|
| baseline (без фильтра и rewrite) | 0.47 | 0.39 | 0.21 | 0.00 | 5.00 | 0.02 |
| filter | 0.47 | 0.39 | 0.25 | 0.75 | 2.53 | 0.02 |
| heuristic | 0.53 | 0.39 | 0.25 | 0.75 | 2.53 | 0.02 |
| llm | 0.53 | 0.44 | 0.25 | 0.75 | 2.53 | 6.83 |
| rewrite | 0.60 | 0.47 | 0.21 | 0.00 | 5.00 | 0.48 |
| rewrite+filter | 0.60 | 0.47 | 0.21 | 0.50 | 4.05 | 0.48 |
| rewrite+heuristic | 0.73 | 0.48 | 0.27 | 0.50 | 4.05 | 0.49 |
| **rewrite+llm** | **0.73** | **0.57** | **0.27** | **0.75** | 4.00 | 8.38 |

LLM `qwen2.5-coder:3b`. Каждый режим кроме baseline и rewrite использует порог 0.62; реранкеры получают
до 20 кандидатов на запрос и возвращают 5.

Выводы:
- **Порог** не меняет, что находится, но отсекает мусор: 3 из 4 вопросов без ответа получают пустой ответ,
  а результатов в среднем вдвое меньше (2.5 вместо 5). Цена — русские вопросы без перевода тоже отсекаются.
- **Rewrite** возвращает русские вопросы: «как удалить запись из базы» находит `Model.delete`,
  «сохранить модель вместе со связанными объектами» — `Model.save_related`.
  Но переписанный мусорный запрос («pandas read_csv…») набирает больше, и порог отсекает его реже (0.50).
- **Эвристика** поднимает правильные ответы, когда слова запроса совпадают с именами (`select_related`, `order_by`).
- **LLM-реранкер** лучше всех ставит правильный ответ первым (MRR 0.57 против 0.39) и сам отбрасывает
  мусор, который прошёл порог после rewrite (rejected снова 0.75). Цена — ~8 секунд на запрос вместо 0.02.
- Размер реранкера важен: с `qwen2.5-coder:1.5b` режим `llm` хуже baseline (hit@k 0.40, MRR 0.27) —
  модель ставит 8/10 нерелевантному коду и 1/10 `QuerySet.paginate`.
- Ни один режим не находит `pre_save`, `transaction` и `prefetch_related`: их нет среди 20 ближайших кандидатов выше порога,
  а второй этап может только переставить или отбросить то, что нашёл первый.

## Настройка порога

На этом индексе релевантные чанки набирают примерно 0.62–0.78, нерелевантные 0.55–0.60
(nomic-embed-text сжимает косинусные скоры в узкую полосу), поэтому порог 0.62 стоит в зазоре.
Русские вопросы без перевода набирают около 0.53, так что порог без переписывания отсекает и их.
